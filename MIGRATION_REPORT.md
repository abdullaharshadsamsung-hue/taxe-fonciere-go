### Other review findings
- [warning] **logic-bug**: The article-code check in bati2018 does not match the copybook it reads, and it is handled differently from nonbati2018. In XCOMBAT, CCOBNB is declared `PIC X`, so EFITA3B8's `IF COMBAT-CCOBNB NOT = 2` is an alphanumeric comparison against "2". The Go `ccobnbDigit` helper instead takes the byte's low nibble, on the assumption (stated in a MIGRATION_NOTE) that XCOMBAT was unavailable and CCOBNB was `PIC 9`. As a result, any byte whose low nibble is 2 passes validation: 'B' (0x42), 'R', 'b', 'r', '"' and so on. The source rejects all of these with CR 12 / RC 01. The same nibble value is then written to RETOURB-CCOBNB as '2'. nonbati2018 compares the raw string (`cb.Ccobnb() != "1"`), which matches its source. Fix: compare `cb.Ccobnb() != "2"` in bati2018.
- [warning] **requirement-drift**: bati2018 has the same rate-provider error problem that was already recorded for nonbati2018, but it was never recorded for this file. When EFITAUX2 or FMSTAU2 returns a Go error, `Calculator.fetch` aborts the whole call. The dispatcher then returns CR 00 with SORTIE left untouched. In EFITA3B8, a failed CALL is caught by `ON EXCEPTION`: it sets CR 24 / RC 01, the calculation continues, and RETOURB is still returned. The two calculators share the same pattern, so a provider error leaves the built-property path returning CR 00 instead of 24/01.
- [info] **inconsistent-pattern**: A test fix loop added `totalsOf` to bati2018 and nothing calls it. It sums only the six TEOM zones and says fees "never enter" TCTOM. `compute` does it a different way: it reproduces the source's out-of-range read of `COTIS-OM(7)` (which is FA300) through `CotisOmSubscript`. The results agree today only because FA300 is still zero at that point. Having two implementations of W-TOTCOT* that disagree is a maintenance trap. Keep one.
